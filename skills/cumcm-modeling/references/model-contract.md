# 模型说明参考

以下八项帮助把建模思路组织成可解释、可实现的说明。按当前任务选用，不必每次填表，也不规定交付文件或审批流程。

## 八项模型合同

| 项目 | 关注的问题 |
|---|---|
| 任务定义 | 每个子问题要求计算、预测、评价或决策什么？ |
| 数据 | 输入字段、单位、范围、质量和来源是什么？ |
| 结论类型 | 最终需要给出哪类结论和指标？ |
| 模型 | 采用什么模型，为什么适配题目？ |
| 数学定义 | 变量、参数、目标函数或控制方程、约束、假设和边界条件是什么？ |
| 实现 | 输入输出、算法步骤、停止条件和依赖是什么？ |
| 验证 | 用什么数据、误差、稳定性或对照检验结果？ |
| 风险 | 哪些条件不满足时需要修订或更换方案？ |

例如，结论目标可以是“输出满足容量与时间窗约束的配送方案，并比较成本和稳定性”，或“输出未来各期预测及其不确定性，并用留出数据检验误差”。这些表述描述答案类型，不提前承诺结果。

## 题目分析的组织参考

题目分析可以覆盖题目与附件、子问题拆解、数据理解与预处理、假设及依据、各问模型与数学定义、算法和验证、实现依赖、风险与文献依据。这些内容可以写进现有方案，也可以在讨论中逐步补充，不要求另建报告或固定顺序。

假设可区分“放宽会改变模型成立条件”与“放宽主要影响近似精度”，并解释为什么要这样简化、影响哪些结论、如何放宽或复验。假设数量由问题需要决定，不把所有假设强行分成两类。

术语说明可包括中文术语、英文术语、符号、定义、单位、首次出现位置及容易混用的词。跨问复用符号时保持含义一致；是否单独建表取决于规模和使用需要。

## 从推导到求解

定义数学对象，说明模型成立的依据，推导关键关系，再集中展示最终模型，解释算法为什么适用。简单模型不必重复汇总。

有目标和约束时说明方向、变量类型与可行域；机理模型说明控制关系和初边值；统计模型说明分析单位、误差结构与估计对象。不要把每种问题都硬写成同一优化形式。

求解说明重点回答：求什么、为什么算法适配、输入输出是什么、何时停止，以及是否受初值、近似误差或计算规模影响。具体到需要编程时，再补足参数和接口细节。

## 与人的讨论和后续工作衔接

优先保留当前选取的理由、尚不确定的条件和已有证据。模型可以先提出推荐，帮助人理解后修订；不要求每项内容都取得形式化批准。

计算反馈使模型变化时，说明变了什么、为何变、影响哪些结果。已有材料直接更新即可，不要求固定版本体系。写论文时使用与实际推导和计算相符的表述，未完成的验证仍写成计划。
