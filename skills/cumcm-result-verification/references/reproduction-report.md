# 复现与证据报告

## 什么才是复现证据

关键结果应能由代码重现，图表应由代码或可追溯数据生成。追踪实际使用的输入、版本、参数、随机种子、运行时与依赖以及复现命令；已有记录足够时沿用，不强制另建记录系统。

按需要保留这些内容：

| 证据 | 解决的问题 |
|---|---|
| 输入和代码路径、版本或 SHA-256 | 核验时使用的是哪份材料，后来是否变化 |
| 实际入口命令、工作目录、参数与运行环境 | 其他人能否按相同条件执行 |
| 随机种子、求解器设置、停止原因 | 如何解释随机波动、预算与求解状态 |
| 退出码、stdout/stderr、输出文件 | 程序是否真的运行，是否有异常或旧文件冒充新结果 |
| 对照值、实测值、误差与容差依据 | “吻合”具体指什么 |

散列只证明文件身份；清单只记录复现条件，不能代替实际运行。未记录种子不一定有问题，例如确定性解析计算；记录固定种子也不保证跨平台逐位一致。

## 重新运行

运行前读入口和输入输出路径，了解是否依赖缓存、手工中间表、绝对路径或交互状态。保留旧结果，在独立目录重跑，尽量避免误读旧缓存。必要时使用干净进程执行笔记本或脚本，检查运行顺序和隐藏状态。

检查退出状态、异常和警告，并确认目标文件由本次运行生成且内容可读。失败或超时时说明实际终止处；原先留在目录中的文件不证明本次成功。

先在相同条件下比较关键数值，再按需要检查环境变化、多种子、不同精度或独立方法。换算法得到相近答案属于交叉核对，不等同于复现原流程。无法完整运行时，可继续静态核查、局部计算或原始约束回代，并明确哪些没有重现。

## 正文与图表对照

论文中每个核心数值应能追溯到实际结果或代码。核对摘要、正文、表格和结论中的重复数值，先确认同名指标是否对应同一子集、时点和统计口径。

检查样本总数能否由分组和处理记录推出；百分比的分母、汇总的权重、单位与合理精度是否一致。同一数值可能代表不同量，不单凭数字相同判为重复或矛盾。

“所有方法都最好”“始终满足”等结论，应核查对应表格中的例外。图注中的样本数、中心统计量、误差棒和检验应与实际计算相符。图中文字正确或图形美观只能说明呈现的一部分，不能证明数据和模型正确。

## 面向人的报告

用最影响可信度的问题开头。对实际检查的项目给出“已通过 / 存在问题 / 无法判断”，可以按需采用以下写法，不要求逐项填表：

> 判断：某项具体结果在什么范围内可信或不可信。  
> 位置与证据：模型式、代码文件与行号、数据行或输出字段；实际值、对照值和运行记录。  
> 影响：改变哪个答案或结论，影响幅度已知还是待算。  
> 建议：局部修复、需要补的材料或最有价值的下一项检查。

“无法判断”给出具体缺口，例如缺原始观测所以无法核对统计推断；不要笼统写“还需更多验证”。同一项目可以同时有已通过的算术与无法判断的现实推广，不必硬合成一个总状态。

结尾回答：哪些结果可保留，哪些需重算，已检证据支持怎样的结论。下列范围逐层判断，不能自动递推：

1. 程序能运行并生成输出。
2. 在记录的输入与环境下能重现关键结果。
3. 输出符合所述数学模型，相关独立检验吻合。
4. 在所检数据、参数和假设下模型获得支持。
5. 对其他时间、群体或现实决策的推广有相应证据。

修改后重跑受影响的检查，并检查后续使用这些量的结果与文字。旧报告保留版本范围；检查后的实质修改不能继续借用原通过结论。
